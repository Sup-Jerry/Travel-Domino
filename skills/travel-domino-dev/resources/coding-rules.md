# 编码规则

## 强制规则
1. 禁止假设任何未给出的代码存在。
2. 需要依赖现有实现时，必须先查看对应源代码。
3. 若缺少关键上下文，先索要代码，再继续修改。
4. 禁止为了“看起来完整”而虚构函数、字段、枚举、组件、工具类。
5. 禁止把示例代码伪装成可直接运行代码。
6. 未确认前，不新增数据库字段、不新增持久化结构。
7. 未确认前，不改动核心实体语义。
8. 未确认前，不进行大规模重构。
9. 优先维持现有命名风格、工程结构与调用链。
10. 所有修改都要说明影响范围。

## 输出要求
- 先分析，后代码
- 代码按文件输出
- 标明替换位置或修改位置
- 如果不确定，明确说不确定，不要补猜测实现
