# 标准输出模板

## 一、需求理解
- 用户要解决什么问题
- 成功标准是什么
- 本次明确不改什么

## 二、影响范围
- 涉及哪些文件
- 哪些模块可能联动受影响

## 三、当前上下文是否足够
- 足够 / 不足够
- 若不足，缺少什么（文件、函数、类型、API 契约、环境约束）
- 是否触发阻断（若触发，停止输出代码）

## 四、技术方案摘要
- 用 1 句话说明核心实现路径

## 五、Functional Spec
### Input
- 数据来源
- 数据格式
- 校验规则

### Processing Logic
- 关键步骤与状态迁移
- 条件分支
- 异常处理

### Output
- 返回结构
- UI 状态变化
- 副作用（网络/存储/导航/日志）

## 六、系统副作用扫描（A-F）
### A. 直接影响范围
### B. 间接影响范围
### C. 潜在副作用清单
### D. 高风险边界场景
### E. 回归测试优先级
### F. 风险缓解建议

## 七、风险等级
- 高/中/低风险项及其理由

## 八、文档来源与版本锚点
- 华为官方文档链接（`developer.huawei.com`）
- 关键 API/规范对应的版本号或发布日期
- 若存在多版本差异，列出差异点与采用策略

## 九、日志与真机验证
- 复现与验证步骤（真机）
- 日志关键字
- 关键日志位置

## 十、修改方案
- 修改思路
- 每个文件改什么
- 为什么这样改

## 十一、实际代码
- 按文件输出
- 不输出猜测代码
- 未通过对齐门禁时本节留空

## 十二、验证方式
- 主流程验证
- 边界场景验证
- 回归风险提示
