# Deep Alignment Playbook

本手册用于支撑 `travel-domino-dev` 的改码前强制门禁。仅在任务涉及代码/配置/API 变更时加载。

## 1) 五大原则

### 原则 1：先技术理解，后实现
- 在进入编码前先确认问题本质、目标、边界、成功标准。
- 未达到高置信度（技术边界、数据流、异常场景、验收标准）不得进入实现。
- 每次改动先评估对现有系统稳定性的影响：功能回归、架构一致性、技术债、运行稳定性。

### 原则 2：精准澄清协议
- 采用增量提问，逐步收敛真实需求。
- 每轮最多 3 个高价值问题；优先提会改变方案方向的问题。
- 把模糊词转成可测技术目标：例如“更快”要落到复杂度、缓存策略或渲染成本。

### 原则 3：上下文中断与核验
- 涉及现有模块时，必须先读取相关代码，不得盲改。
- 涉及 API 时，必须核验 endpoint、参数、响应结构、鉴权方式。
- 涉及环境时，必须核验 HarmonyOS API/SDK/依赖限制。
- 涉及“最新 API/规范/兼容性”时，必须先核验华为官方文档，再给实现建议。

### 原则 4：先产出技术对齐包
- 在编码前先产出结构化方案：摘要、Functional Spec、边界处理、影响范围。
- 对齐包是实现唯一参考源，避免边做边改需求。

### 原则 5：系统级副作用扫描
- 在方案定稿前做链路影响扫描，避免“修一点坏一片”。
- 覆盖直接影响、间接影响、回归风险和防御建议。

## 2) 提问模板（每轮 <= 3 问）

### 意图层
- 你这次要解决的核心问题是什么？成功标准是什么？
- 本次明确不改哪些行为或模块？

### 输入输出层
- 输入数据来源、格式、校验规则是什么？
- 期望输出结构、状态变化、外部副作用是什么？

### 边界异常层
- 网络失败/超时时要显示空态、缓存态还是错误态？
- 并发或重复请求时，以哪次结果为准？

### 契约环境层
- 相关 API 的 endpoint、鉴权、成功/失败响应结构是什么？
- 目标 HarmonyOS API/SDK 版本与依赖约束是什么？

## 3) Functional Spec 模板

### 技术方案摘要
- 用 1 句话描述核心实现路径。

### Input
- 数据来源
- 数据格式
- 校验规则

### Processing Logic
- 关键步骤/状态迁移
- 条件分支
- 异常处理

### Output
- 返回结构
- UI 状态变化
- 副作用（网络、本地存储、导航、日志）

## 4) Side-Effect Scan 模板（A-F）

### A. 直接影响范围
- 直接修改的文件、模块、字段、接口签名、状态字段。

### B. 间接影响范围
- 复用同字段/逻辑的页面与模块。
- 同步/异步流程的耦合点。

### C. 潜在副作用清单
- 数据副作用：字段兼容、历史数据、覆盖风险。
- 逻辑副作用：状态不一致、决策链断裂。
- UI 副作用：显示错误、交互歧义。
- 性能副作用：重复计算、额外请求、渲染开销。
- 可维护性副作用：耦合增加、职责不清。

### D. 高风险边界场景
- 空数据、单条/多条、历史数据、用户修改数据。
- 中途退出再进入、初始化前操作、异步乱序/重复响应。

### E. 回归测试优先级
- 列出最可能受影响的功能与必须回归的交互。
- 标注看似无关但应联测的模块。

### F. 风险缓解建议
- 增加 guard 条件。
- 引入中间状态或职责拆分。
- 增加日志/断言/调试检查点。
- 增加回归测试。

## 5) 风险等级规则
- 高风险：发生概率高且影响核心功能。
- 中风险：可能发生并影响部分体验或子流程。
- 低风险：发生概率低且影响面有限。

每条风险必须写清“等级 + 原因”。

## 6) 阻断规则
- 任一关键上下文缺失：阻断实现。
- 任一关键契约缺失：阻断实现。
- 任一关键环境限制不明确：阻断实现。
- 涉及最新规范但缺少华为官方文档依据：阻断实现。

阻断时输出：
- 缺失项清单（文件/函数/契约字段/环境约束）
- 下一步所需最小补充信息

## 7) 日志与验证模板

### 调试日志要求
- 在关键分支、状态切换、外部调用前后打可检索日志。
- 日志关键字应唯一且可 grep，例如：`[ALIGN_GATE]`, `[FLOW_CHECK]`, `[SIDE_EFFECT_SCAN]`。

### 真机验证要求
- 给出可复现步骤（起始页面、操作路径、预期结果）。
- 给出日志检索关键字。
- 给出日志位置（模块/函数/调用点）。

### 最终验收最小集
- 主流程通过。
- 至少 2 个高风险边界场景通过。
- 回归优先级最高项通过。

## 8) 华为官方文档检索协议

### 适用场景
- HarmonyOS/ArkTS API 用法
- 版本升级、弃用、兼容性约束
- 构建/签名/权限等平台要求

### 来源优先级
1. 华为开发者联盟官方文档（`developer.huawei.com`）
2. OpenHarmony 官方文档（仅在华为文档未覆盖时补充）

### 输出要求
- 至少给出 1 个官方链接；关键 API 建议给出 2 个交叉来源（如 API 说明 + 版本说明）。
- 明确标注版本号、发布日期或文档更新时间。
- 如文档存在差异，先陈述差异，再给保守实现建议。
